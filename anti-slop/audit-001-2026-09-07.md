### 3. Pinch zoom dimatikan di ketiga halaman *(R-03, skill human "Text That Cannot Zoom", WCAG 1.4.4)*

Alasan: `<meta name="viewport" content="... maximum-scale=1.0, user-scalable=no">` di `index.html:5`, `admin/index.html:5`, `tracking/index.html:5` memblokir zoom di iOS/Android. Pengguna low-vision tidak bisa membesarkan teks harga, kode pesanan, atau QR.

Saran: hapus `maximum-scale=1.0, user-scalable=no`. Kalau alasannya mencegah auto-zoom iOS saat fokus ke input, solusinya `font-size: 16px` di input (sekarang 15px di `css/main.css:80`), bukan mematikan zoom.

### 5. Keyboard: modal tidak bisa ditutup dengan Escape, kontrol div tidak bisa dioperasikan *(R-32, R-26)*

Alasan: R-32 mewajibkan semua elemen interaktif bisa dijangkau dan dioperasikan lewat keyboard, dan dialog bisa ditutup dengan Escape. Tidak ada satu pun `onKeyDown` di `src/`.

- **Escape**: tidak ada handler di `Modal.jsx`, `ConfirmDialog.jsx`, `ProfileModal.jsx`, `VariantSheet.jsx`, `QrisModal.jsx`, `QrisViewModal.jsx`, `OrderSummaryModal.jsx`, `AddressPickerModal.jsx`, `TierCompareModal.jsx`.
- **`div` dengan `role="button" tabIndex={0}` tapi tanpa `onKeyDown`** (bisa di-Tab, tapi Enter/Space tidak melakukan apa-apa): `.profile-card` (`CheckoutStep.jsx:144`), `.csf-bar` (`CatalogStep.jsx:127`), `.address-summary-card` (`ProfileModal.jsx:108`).
- **`div` klik tanpa `role`, `tabIndex`, maupun keyboard sama sekali** (tidak bisa dijangkau Tab): `.order-type-card` dan `.date-chip` (`OrderTypeStep.jsx:66-80, 108`), `.ongkir-option-item` (`OngkirOptions.jsx:53`), `.address-picker-result-item` (`AddressPickerModal.jsx:108`), `.image-upload-area` (`ImageUploadDropzone.jsx:44`). Artinya pengguna keyboard **tidak bisa memilih pickup/delivery atau tanggal**, jadi tidak bisa lewat step 1.
- **Focus indicator**: `outline: none` di input (`css/main.css:86`, `css/catalog.css:798, 1414`) diganti perubahan `border-color` ke `--primary` (boleh, itu pengganti yang terlihat). Tapi tidak ada `:focus-visible` custom untuk tombol dan chip, jadi bergantung pada outline default browser yang di beberapa browser mobile tidak muncul.
- `role="dialog"` di `Modal.jsx`, `QrisViewModal.jsx`, `OrderSummaryModal.jsx` tanpa `aria-modal="true"` dan tanpa memindahkan fokus ke dalam dialog saat dibuka.

Saran: (a) satu hook `useEscapeToClose(isOpen, onClose)` dipakai semua modal/sheet; (b) ganti div pilihan jadi `<button type="button">` (order type, date chip, ongkir option, hasil alamat), ini sekaligus menyelesaikan Enter/Space dan Tab; (c) tambah `:focus-visible { outline: 3px solid var(--primary); outline-offset: 2px; }` global.

### 6. Link yang bisa jadi "kosong" tetap dirender *(R-26, R-24)*

Alasan: R-26 melarang link/tombol yang tidak melakukan apa-apa. Beberapa `href` diambil dari settings/env yang boleh kosong, tapi elemennya dirender tanpa syarat, jadi `href=""` (klik = reload halaman) atau `wa.me/undefined`.

- `OrderTypeStep.jsx:139-151`: link Instagram dan TikTok di footer selalu tampil, walau `instagram_url`/`tiktok_url` kosong (SettingsTab memperlakukannya opsional).
- `OrderTypeStep.jsx:91` dan `CheckoutStep.jsx:113`: "Buka di Google Maps →" dengan `href={storeMapsUrl}` yang default-nya `''` (`config.js:8`).
- `OrderTypeStep.jsx:22`, `CatalogStep.jsx:22`: `waLink(config.adminWhatsapp, ...)` menghasilkan `https://wa.me/undefined?...` kalau `VITE_ADMIN_WHATSAPP` tidak di-set. Ini juga menular ke `QrisModal.jsx:64` (`waUrl`).

Saran: render link hanya kalau URL-nya ada (`{instagramUrl && <a ...>}`), dan untuk WA admin, kalau nomornya kosong sembunyikan tombol bantuan. Untuk `waUrl` di checkout, lebih baik gagal keras di build (`config.js` melempar error kalau `VITE_ADMIN_WHATSAPP` kosong) karena tanpa itu order tidak bisa dikonfirmasi.

### 7. Error state tidak pernah ditampilkan di admin *(R-27)*

Alasan: R-27 mewajibkan empty, loading, **dan** error state. `useProducts`, `useOrders`, `usePromos` sudah mengembalikan `error`, tapi tidak ada tab admin yang memakainya. Kalau fetch gagal (RLS drift, koneksi putus, token expired), `products.length === 0` dan yang tampil adalah empty state "Belum ada produk / Belum ada pesanan", yang menyesatkan admin. `DashboardTab` juga tidak punya error state (angka 0 tampil seolah data valid).

Lokasi: `ProductsTab.jsx:56-80`, `OrdersTab.jsx:111-128`, `PromoTab.jsx:55-70`, `DashboardTab.jsx:118-126`, `SettingsTab.jsx:83-90`.

Saran: satu komponen `AdminErrorState` yang menyebutkan apa yang gagal dan tombol "Coba lagi" (`refetch`), dirender sebelum cabang empty. Sekalian cek `useSettings` yang sekarang fail-silent (customer fallback ke `config.js` itu benar, tapi di admin, admin perlu tahu tabel `settings` belum ada).

### 8. Aset dan copy khusus kedai kopi hardcoded di template multi-klien *(R-23, R-38; CLAUDE.md "sisa referensi Breva = bug identitas")*

Alasan: R-23 melarang aset visual yang diasumsikan tanpa instruksi. Untuk klien non-kopi (bakery, nasi box, catering) yang memakai template ini, semua di bawah ini adalah asumsi yang salah dan tidak bisa diganti dari admin:

- Placeholder gambar produk `☕`: `ProductCard.jsx:34`, `VariantSheet.jsx:66`, `CheckoutStep.jsx:169`, `OrderStatusCard.jsx:45`, `ProductsTab.jsx:87`.
- `☕` hardcoded, bukan `settings.brand_icon`: `CatalogStep.jsx:78` (`banner-deco`), `QrisModal.jsx:94`, `QrisViewModal.jsx:44`, admin `App.jsx:35`, `LoginScreen.jsx:30`, `DashboardTab.jsx:144` (ikon "Item Terjual").
- Copy: `ShippingLoadingOverlay.jsx:10-12` (`☕` + "biar **kopimu** ga lama nyampe!"), `whatsapp.js:93` ("Terima kasih sudah order di X! ☕").
- Placeholder form admin: `ProductFormModal.jsx` ("Contoh: Kopi Latte Susu", "Espresso + susu oat, tersedia hot/iced").
- `images/test`: file 1 byte sisa percobaan, ikut ter-commit.

Saran: semua slot ikon membaca `settings.brand_icon` (yang sudah ada), placeholder produk pakai inisial nama produk atau blok geometris netral, copy loading overlay dibuat netral ("biar pesananmu cepat sampai"), placeholder form netral ("Contoh: Nama Produk"). Hapus `images/test`.

## MEDIUM (Purpose-Gate)

### 9. Emoji sebagai dekorasi di label tombol, tab, dan judul *(R-04, skill ui "Emoji as Decoration")*

Alasan: skill ui menyebut emoji yang tersebar di tombol/heading sebagai tell paling keras. Sekitar 120 kemunculan di `src/`. Yang jelas dekorasi (label sudah menjelaskan semuanya):

- Semua tab admin (`App.jsx:14-18`: 📊 🛍 🎟 📦 ⚙️), tombol admin (`✏️ Edit`, `🗑️ Hapus`, `📤 WA Customer`, `🖨️ Print Label`, `✅ Konfirmasi`, `❌ Batalkan`, `⬇ Export CSV`, `⬆ Import CSV`, `📋 Detail`), ikon stat dashboard (💰 📦 ☕ 📈 👀), tag produk (`👁 Tampil`, `🙈 Disembunyikan`, `✨ New`).
- Customer: `💬 Butuh bantuan?`, `📷 Tampilkan QR lagi`, `📦 Simpan kode ini...`, `Bayar via QRIS 💳`, `📦 Lacak Pesanan`, `⬇ Simpan QR`, header seksi `📦 PESANAN`, `👤` avatar profil.
- Toast: ✅/❌/ℹ️ (`Toast.jsx:5`) plus emoji lagi di dalam pesan (`... ✅`, `... 🎉`), jadi dobel.

Ini bukan larangan mutlak. Emoji sebagai suara brand UMKM yang santai itu alasan yang sah **kalau ditulis** dan dosisnya dijaga. Saran pembagian: **pertahankan** emoji yang membawa informasi dan konsisten (🏠 Pickup / 🛵 Delivery, status pesanan ⏳🆕✅❌ yang sama di admin, tracking, dan WA, `brand_icon` dari settings). **Hapus** dari label tombol, tab admin, judul seksi, ikon stat, dan pesan toast yang sudah punya ikon.

### 10. Panah di hampir semua CTA *(R-08)*

Alasan: R-08 menyebut panah bukan identitas default tombol; kalau dipakai, alasannya ditulis.

`Lihat Menu →` (`OrderTypeStep.jsx:132`), `Lanjutkan →` (`CatalogStep.jsx:138`), `Buka di Google Maps →` (dua tempat), `Lihat semua paket →` (`TierBadge.jsx:38`), `Simpan kode ini buat lacak ... →` (`OrderSummaryModal.jsx:98`), `›` di `.profile-card-arrow`.

Saran: panah masuk akal di CTA yang benar-benar "maju ke step berikutnya" (Lihat Menu, Lanjutkan) sebagai motif "flow 3 langkah"; tulis itu sebagai alasannya di DESIGN.md dan hapus dari link eksternal (Maps, tracking) yang sudah membuka tab baru.

### 11. Label uppercase dengan tracking lebar, dan kalimat kapital semua *(R-06, skill copywriting "All-Caps Emphasis")*

Alasan: R-06 menandai uppercase + letter-spacing lebar sebagai default AI kecuali ada alasan tertulis.

- Label seksi: `.co-section-title` (`css/catalog.css:632`, 0.08em), `.vs-group-name` (`:1338`, 0.08em), `.pickup-info-label` (`:150`), `.date-section-label` (`:166`), `.co-meta-label` (`:659`), `.oss-card-label`/"KODE PESANAN" (`:386`), `.oss-section-header` "PENGIRIMAN"/"PESANAN" (`OrderSummaryModal.jsx:105, 119`), `css/admin.css:296, 593`.
- Prosa kapital: `WAJIB — KIRIM FOTO BUKTI PEMBAYARAN` (`OrderSummaryModal.jsx:80`). Judul "Satu langkah lagi!" dan subjudulnya sudah menjelaskan hal yang sama dengan lebih manusiawi.

Saran: pilih satu gaya label seksi (misalnya sentence-case 13px bold `--text-mid`) dan pakai konsisten. Ganti baris peringatan kapital jadi kalimat biasa: "Wajib: kirim foto bukti pembayaran lewat WhatsApp, kalau tidak pesanan tidak diproses."

### 12. Animasi masuk template di banyak elemen, tanpa `prefers-reduced-motion` *(R-19)*

Alasan: R-19 minta animasi punya tujuan UX tertulis dan sesuai dial MOTION. Yang ada sekarang adalah pola fade-up default:

- `fadeUp` di **setiap** `.product-card` dengan stagger 60 ms (`css/catalog.css:414`, `ProductCard.jsx:25`), `slideUp` di setiap step (`:7`), `fadeUp` di `.pickup-address-card` dan `.date-section` (`:144, 161`).
- Admin: `fadeInUp` di login card, product card (stagger 55 ms), order card (`css/admin.css:22, 255, 735`).
- Tidak ada `@media (prefers-reduced-motion: reduce)` di seluruh CSS (0 hasil).

Yang **bukan** masalah: loop `sloDrive/sloSteam/sloRoad/sloDot` di overlay ongkir hanya jalan selama request Biteship berlangsung (ada trigger dan akhir), itu loading indicator yang punya tujuan. `pop`/`bounce` di stepper qty adalah feedback aksi, juga punya tujuan.

Saran: pertahankan transisi step (memberi arah "maju") dan feedback tombol, hapus stagger fade di kartu produk/admin (menunda tampilnya harga di list yang panjang), dan tambah blok `prefers-reduced-motion` yang mematikan semua `animation` kecuali spinner.

### 13. Dashboard admin memakai "shell dashboard default" *(skill ui "Default Dashboard Shell", C-3, R-20)*

Alasan: lima stat card berukuran sama, dua chart batang, pill status, lalu daftar. Angkanya **nyata** (dihitung dari `orders`), jadi ini bukan pelanggaran R-17. Masalahnya hierarki: keputusan yang admin ambil di dashboard adalah "ada pesanan yang perlu dikonfirmasi tidak?", dan angka `pending` justru paling kecil di layar (pill di bawah dua chart, `DashboardTab.jsx:198-205`), sementara badge merah di tab Pesanan sudah menjawab hal yang sama.

Saran: jadikan "N pesanan menunggu konfirmasi" fokus pertama (kartu besar, tombol langsung ke tab Pesanan filter pending), pendapatan hari ini nomor dua, sisanya boleh mengecil atau jadi satu baris. Tulis satu kalimat tujuan tiap chart di judulnya, misalnya "Pendapatan per hari, 7 hari terakhir (hanya pesanan terkonfirmasi)" karena aturan REVENUE_STATUSES itu tidak terlihat oleh admin.

## LOW (Quality Locks dan kerapian)

### 14. Tidak ada DESIGN.md dan alasan desain tidak tertulis *(R-37, R-31, R-21)*

Alasan: R-37 minta arah desain tertulis, R-31 minta satu baris alasan per keputusan besar. Arahnya sebenarnya sudah ada dan konsisten (palet cokelat kopi + cream + aksen latte, Plus Jakarta Sans, radius 10/16/22/28, mobile-first 480 px), tapi hanya hidup di CSS. Tanpa DESIGN.md, klien berikutnya yang bukan kedai kopi akan mewarisi palet kopi tanpa ada yang menandai itu sebagai keputusan yang perlu diganti (lihat #8).

Saran: buat `DESIGN.md` singkat berisi: identitas (template F&B UMKM, hangat, santai), palet dengan catatan "ganti per klien", tipografi dan alasannya, dial yang saya baca dari kode: **ENERGY 2 / RHYTHM 1 / MOTION 2** (kartu dan step seragam itu disengaja untuk flow pesan yang cepat), alasan tema terang tetap (R-21: identitas cream/cokelat dan konteks katalog makanan, bukan alat developer), alasan emoji sebagai suara brand (#9), alasan panah di CTA step (#10). Sekalian tambahkan blok pointer antislop di `CLAUDE.md` seperti instruksi wizard di `antislop.md`.

### 15. Palet inti rapi, tapi ~60 literal hex di luar token *(R-29)*

Alasan: R-29 minta palet dikelola sebagai sistem. Token di `css/main.css:7-26` bagus (2 inti + 1 aksen + netral). Tapi `catalog.css`/`admin.css`/`tracking.css` punya puluhan literal: warna status (`#c05000/#fff3e0`, `#1565c0/#e3f2fd`, `#2e7d32/#e8f5e9`, `#16a34a/#dcfce7`, `#1a7a3c/#e7f7ef`, keduanya untuk "selesai" tapi beda), `#a08878`, `#c4a898`, `#7a5538`, `#2d1a0e`, dan `#a05230` inline di `OrderSummaryModal.jsx:44, 54`.

Saran: tambah token semantik (`--status-pending-bg/fg`, `--status-done-bg/fg`, `--wa-green`) dan pakai di ketiga app supaya perbaikan kontras (#4) cukup di satu tempat.

### 16. `100vh` di admin, `100dvh` di customer *(skill layoutmobile "100vh Sections")*

`css/admin.css:7, 54` pakai `min-height: 100vh` (login screen dan layout admin), sementara customer dan tracking sudah `100dvh`. Di Chrome Android, `100vh` lebih tinggi dari area terlihat, jadi login card bisa terpotong browser chrome. Ganti ke `100dvh`.

### 17. Em dash dan banner dekoratif di komentar kode *(R-02 di komentar, skill code "Decorative Separators")*

- 40+ em dash di komentar JS (`CartContext.jsx`, `useShipping.js`, `orders.js`, dst) dan 11 di komentar CSS. Skill code tidak melarang em dash secara khusus, tapi R-02 berbunyi "any text"; ini opsional dan tidak mempengaruhi user.
- Banner `/* ===== ORDI MASTER — SHARED STYLES ===== */` (`css/main.css:1-3`), `css/tracking.css:1-4`, `css/admin.css:1060-1062`: pola separator berulang yang skill code sebut sebagai tell. Ganti jadi satu baris komentar biasa.

Komentar selebihnya justru contoh yang bagus (menjelaskan *kenapa*, bukan *apa*: alasan `stopPropagation` di AddressPicker, alasan portal `#printLabel`, alasan `REVENUE_STATUSES`). Jangan dihapus.

### 18. Label bahasa campur di badge *(R-16 ringan, konsistensi)*

Badge `✨ New` (`ProductCard.jsx:28`, `ProductsTab.jsx:94`, `ProductFormModal.jsx:165`) satu-satunya label Inggris di UI yang seluruhnya Indonesia. "Baru" cukup. Placeholder banner "Ada yang baru nih! ✨" (`SettingsTab.jsx:165`) juga menyisipkan emoji ke konten klien.

### 19. Toast sukses membawa emoji dobel dan sebagian pesan berakhir "ya!" berulang
